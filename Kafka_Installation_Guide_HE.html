מדריך התקנה — Kafka ו־OpenSearch

הכנת Windows, Cursor, uv ו־Docker Desktop למחברות הלימוד המקומיות ולחלופת Kafka בענן. פקודות קצרות, בדיקת חיבור והסבר היכן מריצים כל שלב.

מתחילים כאן | מדריך התקנה | הסבר מלא לשתי המחברות

עובדים עם Confluent Cloud? מחברת 03 משתמשת ב־Kafka בענן. בצעו את התקנת Python/uv ואת הכנת OpenSearch, ודלגו על הפעלת Kafka המקומי בסעיף 4. את הקמת האשכול, ההרשאות וקובץ החיבור מבצעים לפי מדריך הענן.

1. מה מורידים ולמה?

ההוראות מיועדות ל־Windows עם Cursor מקומי ו־Docker Desktop במצב Linux containers. במחברות 01 ו־02 אין צורך בחשבון ענן; מחברת 03 משתמשת ב־Confluent Cloud. המחברת הראשונה צריכה Kafka; השנייה צריכה גם OpenSearch וחיבור אינטרנט ל־Wikimedia.

רכיב פעולת ההתקנה
Gitהורידו את מתקין Windows והשלימו התקנה. פתחו מסוף חדש לאחר מכן.
Cursorהתקינו ופתחו. בחלונית Extensions התקינו Python ו־Jupyter; המזהים הם ms-python.python ו־ms-toolsai.jupyter.
uvהשתמשו בפקודת ההתקנה הרשמית בהמשך. uv יתקין גם את גרסת Python הנדרשת.
Docker Desktopהתקינו את גרסת Windows לפי ההוראות הרשמיות, כולל WSL 2 אם הוא אינו מותקן. הפעילו מחדש את Windows אם המתקין מבקש.

להתקנת uv ב־PowerShell, לפי התיעוד הרשמי:

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

סגרו ופתחו מחדש את המסוף לאחר ההתקנה, ובדקו:

git --version
uv --version

2. מורידים את הפרויקט ופותחים תיקייה

ב־PowerShell:

git clone https://github.com/paulavrahami/kafka-python-lesson.git
cd kafka-python-lesson

ב־Cursor בחרו File → Open Folder ופתחו את kafka-python-lesson. פתחו Terminal → New Terminal. כל הפקודות הבאות פועלות מתוך אותה תיקייה, שבה נמצאים pyproject.toml, uv.lock, המחברות והתיקייה scripts.

אם כבר הורדתם את הפרויקט, אין צורך לשכפל שוב. שמרו שינויים שלכם, ועדכנו את העותק באמצעות Git. אם Git מציג התנגשות עם שינויים מקומיים, פתרו אותה לפני החלפת קבצים; אין צורך למחוק את תיקיית העבודה.

git pull
uv python install 3.13.12
uv sync --locked

בהורדה חדשה, git pull אינו נדרש; מתחילים בשתי פקודות uv. uv sync --locked יוצר .venv ומתקין את החבילות מהנעילה. אין להפעיל pip מתוך המחברת. אם ה־Kernel כבר פועל, עצרו אותו לפני סנכרון הסביבה, במיוחד ב־Windows.

3. פותחים Docker Desktop ומוודאים שהוא פועל

  1. פתחו את תפריט Start, הקלידו Docker Desktop ופתחו את היישום.
  2. המתינו עד שהמנוע פועל. השתמשו ב־Linux containers; ההוראות אינן מיועדות למכולות Windows.
  3. פתחו את לשונית Containers. אחרי פקודות ההפעלה בהמשך יופיעו בה Kafka ו־OpenSearch.
docker version

הפלט צריך לכלול גם Client וגם Server. אם רק Client זמין או מתקבלת שגיאת חיבור למנוע, השלימו את עליית Docker Desktop לפני הרצת סקריפטי המעבדה.

4. מפעילים Kafka ובודקים חיבור

במסוף הפרויקט:

uv run --locked python scripts/kafka_docker.py start
uv run --locked python scripts/check_kafka.py

התמונה הקבועה היא apache/kafka:4.4.0, שם המכולה kafka-python-lab, וכתובת ה־Kernel המקומי היא 127.0.0.1:9092. ההורדה הראשונה יכולה להימשך מספר דקות. start מוריד תמונה חסרה, יוצר מכולה חסרה או מפעיל את הקיימת, וממתין למוכנות.

הבדיקה check_kafka.py קוראת metadata בפרוטוקול Kafka ובודקת גם כתובות שה־Broker מפרסם. היא אינה יוצרת Topic ואינה שולחת אירועים. שורת הצלחה מתחילה ב־SUCCESS: host-to-Kafka metadata connection works.. גם אפס Topics בתחילת העבודה הוא תקין.

כעת אפשר לעבוד עם מחברת 01. לפרויקט 1 אין צורך ב־OpenSearch.

5. מכינים את המחשב ל־OpenSearch

המעבדה משתמשת ב־opensearchproject/opensearch:3.10.0, כפי שמוגדר בסקריפט. לפי תיעוד OpenSearch Docker, נדרשים לפחות 4 GB זיכרון ל־Docker Desktop. Kafka, Cursor ושאר המחשב צורכים זיכרון נוסף; ודאו שנשאר מרווח גם להם.

ב־Docker Desktop עם Hyper-V אפשר למצוא הגבלת זיכרון ב־Settings → Resources. ב־WSL 2 הזיכרון מנוהל בהגדרות מכונת WSL, ולכן ייתכן שלא יופיע שם מחוון זיכרון. ראו את ההבחנה בתיעוד Docker.

ב־Windows עם Docker Desktop ו־WSL 2, הגדירו את vm.max_map_count של מארח Docker. תחילה, ב־PowerShell:

wsl -d docker-desktop

כעת אתם בתוך מעטפת Linux של Docker Desktop. הריצו שם:

sysctl -w vm.max_map_count=262144
exit

הפקודה exit מחזירה ל־PowerShell. ההגדרה נעשית במארח WSL של Docker, ולא בתוך מכולת OpenSearch. ייתכן שתצטרכו לחזור עליה לאחר הפעלה מחדש. אם ההפצה אינה נמצאת, ודאו ש־Docker Desktop פועל במצב WSL 2 ופעלו לפי הוראות Windows הרשמיות.

6. מורידים ומפעילים את OpenSearch

uv run --locked python scripts/opensearch_docker.py start

הסקריפט מוריד את התמונה אם היא חסרה, מכין volume נתונים וממתין לתשובה מ־HTTP. בסיום תקין אפשר לפתוח בדפדפן http://127.0.0.1:9200 ולקבל פרטי שרת ב־JSON.

פרט הערך במעבדה
מכולהopensearch-python-lab
תמונהopensearchproject/opensearch:3.10.0
כתובתhttp://127.0.0.1:9200
אחסון מסמכיםopensearch-python-lab-data — volume הנשמר גם לאחר stop.
תצורהשרת יחיד, אימות ו־TLS כבויים, פורט קשור ל־127.0.0.1. מתאים למעבדה מקומית.

המחברת משתמשת ב־API של OpenSearch דרך Python. אין צורך להתקין OpenSearch Dashboards. יעד מרוחק דורש כתובת HTTPS והגדרות אבטחה מתאימות; אין לשנות את המעבדה המקומית לחשיפה ברשת כדי לפתור בעיית חיבור.

7. בוחרים Kernel ומריצים את המחברת הנכונה

  1. פתחו תחילה את 01_Kafka_Synthetic_HE.ipynb ב־Cursor.
  2. לחצו Select Kernel. אם צריך בחרו Select Another Kernel → Python Environments.
  3. בחרו .venv\Scripts\python.exe. תא האבחון צריך להציג Python 3.13.12 ואת סביבת הפרויקט.
  4. השאירו USE_KAFKA = True והפעילו Restart Kernel and Run All. צפויים עשרה אירועים, שישה בוטים וארבעה שאינם בוטים.
  5. לאחר שהבנתם את התוצאה, פתחו את 02_Wikimedia_Streaming_OpenSearch_HE.ipynb. הפעילו לפי הסדר את ההגדרות, בדיקת החיבורים ותא הזרם.

במחברת 02 ההגדרות MAX_EVENTS = None ו־MAX_SECONDS = None מפעילות זרם ללא תקרה כוללת. תא הזרם אינו אמור להסתיים מעצמו. לחצו על עצירת התא, המתינו לסגירה, ובטלו את המשך Run All אם נדרש. לאחר מכן הפעילו ידנית את תאי הדוח והשאילתות.

8. בדיקת מצב, לוגים ועצירה

uv run --locked python scripts/kafka_docker.py status
uv run --locked python scripts/kafka_docker.py logs
uv run --locked python scripts/opensearch_docker.py status
uv run --locked python scripts/opensearch_docker.py logs

הפסיקו תחילה את תא הזרם והמתינו לסיום הסגירה. לאחר מכן:

uv run --locked python scripts/opensearch_docker.py stop
uv run --locked python scripts/kafka_docker.py stop

פקודות העצירה משאירות את המכולות במקומן. OpenSearch שומר את הנתונים ב־volume; Kafka משתמש שוב באותה מכולה ובנתוניה בהפעלה הבאה. מחיקת מכולת Kafka או volume של OpenSearch היא פעולה נפרדת ועלולה לאבד נתונים; היא אינה שלב נדרש בהתקנה.

9. פתרון תקלות לפי הסימן

הסימן הבדיקה הבאה
uv is not recognizedפתחו מסוף חדש אחרי התקנת uv, בדקו uv --version וחזרו למדריך ההתקנה הרשמי.
ה־Kernel אינו 3.13.12 או שחסרה חבילהעצרו את ה־Kernel, הריצו uv sync --locked ובחרו מחדש את .venv של הפרויקט.
Docker אינו זמיןפתחו Docker Desktop, המתינו לעליית המנוע ובדקו docker version.
Message timed out או שגיאת advertised addressהריצו check_kafka.py ואת logs. ודאו שה־Kernel פועל מקומית ושהכתובת היא 127.0.0.1:9092. מדריך Kafka מפרט בדיקות נוספות.
OpenSearch יוצא מיד או מציין vm.max_map_countבדקו את logs, את ההגדרה במארח Docker בסעיף 5 ואת הזיכרון הזמין.
פורט 9092 או 9200 תפוס / שם מכולה כבר קייםבדקו Containers ב־Docker Desktop. הסקריפטים מסרבים להחליף משאב בעל הגדרות אחרות; אל תמחקו אותו לפני בירור.
תא הזרם ממשיך לרוץצפוי בפרויקט 2. בדקו דוחות STREAM ועצרו ידנית כשתרצו לעבור לשאילתות.
אין תוצאות לאתר העבריייתכן שטרם התקבל אירוע מתאים. בדקו את count והרשומות האחרונות או חפשו אתר שהופיע בפלט.
מספר הסיכומים שונה ממספר המסמכיםהסיכומים במחברת מוגבלים ל־15 הדקות האחרונות לפי זמן האירוע; count כולל את האינדקס כולו.

כתובת localhost מתייחסת לסביבה שממנה רץ ה־Kernel. ההוראות כאן מניחות Kernel מקומי ב־Windows. עבודה בתוך WSL, Dev Container או מחשב מרוחק מחייבת בדיקת רשת בהתאם למיקום ה־Kernel; אין להניח שאותה כתובת תמיד תוביל לאותו שרת.
